    步驟 3 / 5

    界定修改範圍與驗收方式

    Legacy Coding Task 只把路徑寫入代理需求，不會技術強制。

    每行一個 repository-relative path；. 表示整個 repository，結尾 / 表示 subtree，沒有結尾 / 只比對 exact path。

    Immutable v2 任務必須至少指定一個 allowed path；若允許整個 repository，請明確填入 .。

    獨立的 machine-readable path policy；prohibited path 優先於 allowed path。

    Prohibited path policy 格式無效。

    唯讀預檢：對照目前 pinned 版本的實際檔案，不會擋住送出。0 命中不一定是錯（規則可能指向即將新建的檔案）；exact 規則命中既有目錄名幾乎一定是想寫成 xxx/。

    給代理與核准者的 advisory 要求；不會取代上方 machine-readable prohibited paths，也不會被當成 path policy 技術強制。

    步驟 4 / 5

    選擇驗證需求並理解權限邊界

    「技術強制」與「代理要求」分開呈現；本表單不會授予新的 command 或 network 權限。

    只映射現有 validation_target；不會自動建立或執行 worker Job。

    請選擇 validation target，或取消 worker validation。

    禁止自由文字 secret；啟用 opaque reference 前需要另外選定 broker 與 scope model。
